# 简历展示与上线验收说明

## 结论

当前版本可用于本地演示与简历项目讲解，已具备网页操作、三栏工作台（左栏卡片目录与会话窗口、中栏输入与结果视图、右栏对话）、SSE 实时执行过程（时间线 + 结果卡片目录）、真实工具分析、知识检索、条件编排、报告生成、会话内受控追问与会话内自由问答、会话落盘（刷新页面或重启服务后可恢复历史会话与对话）及失败回退。定位是**工作流式工业诊断助手原型**：LangGraph 按固定步骤运行，模型不自主规划任务。

本次未发布公网地址，Docker 镜像尚未实际构建；不能把本地通过视为公网部署完成。

## 首次访问的体验

1. 打开首页即默认选择正常基线与外圈故障样例，无需注册或自备文件。
2. 点击“一键演示”即可分析；演示按钮会先清除旧上传文件，避免文件优先级干扰。
3. 模型等待期间显示当前阶段与已等待秒数，并禁止重复提交或修改本次输入。
4. 分析过程实时显示 Agent 执行时间线（节点与工具状态、分支原因）；完成后常驻显示结论横幅与摘要（置信等级、候选、RMS 变化、工具调用、耗时），页面为三栏工作台：左栏是卡片目录与会话窗口列表（一次诊断 = 一个会话窗口，可切换历史），中栏是输入与所选视图。
5. 卡片目录点击切换对应内容：决策依据、关键证据、信号分析（频带 / 频谱 / 包络谱）、知识检索与来源、数据质量与复核、完整报告（可下载 Markdown）、执行过程（含执行统计与 trace）与诊断追问（受控，7 个固定问题，回答只基于本次会话事实）。
6. 右栏是与模型的对话对话框：自由提问的回答限制在当前选中会话的事实内，模型回答须通过「候选白名单 + 会话来源」两道校验，否则降级为确定性回答；模型不可用时明确标记降级原因，无依据时答「当前诊断记录无法支持该结论。」。
7. 会话与对话消息落盘在服务端 SQLite（默认 `data/sessions.db`），刷新页面或重启服务后左栏会话窗口、执行时间线与右栏对话记录会自动恢复，可继续在同一会话内追问；超过 50 个会话时按创建时间淘汰最旧的。
8. 手机可查看摘要，宽表与图表在容器内横向滚动。接口报错直接显示原因，并清除上一份结果。

## 上线方式

这是有 Python 后端的应用。静态页面可以展示界面，但实际分析和模型调用需要服务器；简历链接应指向前后端一起运行的服务。

最少只需一个能运行 Python 的服务，FastAPI 已同时提供网页和 API，无需再拆一个前端服务。部署平台需安装 requirements.txt，复制 app 与 data/samples，并把模型凭据放入服务端环境变量。

建议演示配置：

```dotenv
MCP_MODE=local
ENABLE_HYBRID_RETRIEVAL=false
USE_LLM=auto
LLM_TIMEOUT=20
LLM_MAX_RETRIES=1
MAX_UPLOAD_BYTES=20971520
SESSIONS_DB_PATH=data/sessions.db
CHAT_HISTORY_TURNS=3
AUDIO_DIR=data/audio
AUDIO_MAX_FILES=200
```

MODEL_API_BASE、MODEL_API_KEY、MODEL_NAME 填入服务器私密配置。网页不需要密钥。USE_LLM=never 可用于断网演示或暂时停用付费调用；页面会标明实际报告模式。

会话与对话消息落盘在 `SESSIONS_DB_PATH` 指向的单个 SQLite 文件里：容器或托管平台若要跨重启保留历史会话，需要把该文件放在持久化磁盘 / 卷上（例如 `-v "${PWD}/data:/app/data"`），否则实例重建即清空。该存储为单机文件、**多副本不共享**，`--workers 1` 与该设计一致。

原始波形的 WAV 旁挂文件落在 `AUDIO_DIR`（默认 `data/audio`），按 `AUDIO_MAX_FILES`（默认 200）保留最新的若干个、超出即按修改时间淘汰最旧的。它与会话库同样是**单机本地盘、多副本不共享**；云平台若使用只读文件系统或不给写盘权限，音频落盘会失败——此时诊断仍能完成并给出结论，只是「信号分析」卡片里的播放器显示「无可播放音频」（`trace.warnings` 里会留一条提示），不影响曲线与报告。

容器构建与运行示例（**尚未在本机验证**）：

```sh
docker build -t bearing-diagnosis .
docker run -d --name bearing-demo --restart unless-stopped --env-file .env -p 127.0.0.1:8000:8000 bearing-diagnosis
```

此示例把服务绑定服务器回环地址，需要反向代理或托管平台对外提供 HTTPS。容器化不是唯一方式；平台直接运行 Python 服务也可以，启动命令为：

```sh
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1 --limit-concurrency 8
```

按实际平台修改端口。并发上限是演示起始配置，**不等于性能评测结论或按 IP 限流**。

## 公网发布前仍需完成

1. **选定部署位置并实际启动服务**：当前未提供部署账号、域名或服务器，尚无公网链接。
2. **保护付费调用**：当前应用没有按访问者限流或每日额度。公网匿名演示应在网关配置请求频率、并发与请求体上限，并在模型侧设置预算；未完成前可以先用模板模式。
3. **入口限制请求大小**：应用的 20 MB 是解析 multipart 后对单文件的检查，不能替代网关在接收请求时的大小限制。两文件总请求需包含额外 multipart 开销。
4. **验收真实部署**：从另一台设备打开 HTTPS 首页，运行外圈样例、无变化样例及错误输入，检查日志、报告下载、模型失败回退。冷启动、持续并发、跨地区网络和长期成本均未测量。
5. **交付文件范围**：.env 已被 Git 忽略和 Docker 排除；上传代码或打包时同样不要包含它。.venv、work 日志、data/chroma 本地索引与 data/sessions.db 会话库也不必交付。

## 数据与能力边界

- 公开样例来自 CWRU，只有单一工况与 1 秒片段，不等于企业真实生产数据。
- 已知滚动体样例的历史误判（修正前输出 `inner_race_fault` 0.4614，与内圈样本得分相同）本轮已修正为正确候选 `ball_fault`（score **0.6283**、`frequency_family=BSF`、置信度 low）：滚动体条目补「包络能量分散、无单一主导族」判据并声明族元数据，编排层按「并列时首位候选声明的族落在并列族内才采信」给出结论。但 BPFI 与 BSF 包络能量仍只差 **7.06%**（并列未消除）、结论不代表主导族已确定、采信依赖条目 `frequency_family` 元数据，**仍需人工复核**，如实保留在演示与评测中。
- 混合检索试运行曾出现错误排序，默认关闭；实现了向量路径不代表其真实召回质量已通过。
- 候选类型字段有程序约束，但模型自由文本仍可能出错；不能宣称彻底消除幻觉。
- 默认 local 调用复用工具实现；需要演示实际 MCP 协议时显式使用 stdio。
- 若没有部门试用、验收及对比记录，简历宜写“基于工业故障分析工作流程开发辅助诊断与报告生成原型”，不要写成已在公司上线或已实现量化提效。
